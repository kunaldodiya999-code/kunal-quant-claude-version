## 1. Architecture map

```
FYERS WebSocket ticks
  -> paper_trading/fyers_feed.py           (socket wrapper, read-only)
  -> market_data/live_ticks.py             (ticks -> 1-minute candles)
  -> paper_trading/market_data_pipeline.py (1m -> 1/3/5m bars, calls signal evaluator)
  -> paper_trading/uni_lite_signals.py     (NEW: KTMI Uni Lite arrows -> PaperSignal)
  -> paper_trading/coordinator.py          (duplicates, controls, loss cap, kill switch)
  -> paper_trading/pending_entry_orchestrator.py + entry_adapter.py
       (contract resolve, option subscribe, fresh quote check)
  -> paper_trading/sizing.py               (allocation -> whole lots)
  -> paper_trading/engine.py + buyer_lifecycle.py (simulated position, SL/target)
  -> paper_trading/exit_manager.py + tsl_shadow_lab.py (6 trailing stops, checkboxes)
  -> paper_trading/recorder.py + recovery.py (CSV journals, restart rebuild)
  -> paper_trading/account.py + costs.py   (equity, charges)
Composition root: paper_trading/session.py
```

## 2. KTMI Uni Lite status

- **Done today:** locked Pine source, compact Pine, Python mirror, parity tests,
  paper engine now uses Uni Lite by default (`signal_profile="UNI_LITE_CORE"`).
- **Fixed differences:** the old path used Long Speed on Close (Uni Lite: High),
  had no "speed > signal" / "speed > 0" checks, and crossed at the trigger
  slightly differently from TradingView. The old path is still selectable as
  `LEGACY_UNIVERSAL`.
- **Open:** no warm-up history at session start (see section 8, item 1).

## 3. Paper engine and persistence

Full buyer-only lifecycle exists: signal -> contract -> fresh quote -> sizing
-> simulated entry -> SL / 3R target / trailing / forced exit -> CSV journals
(signals, trades, rejections, exit events) -> restart recovery. Persistence is
CSV files under `data/paper_trading/`, not the SQLite database.

Initial stop 30% below premium, 3R target, 6 trailing methods (checkboxes),

## 7. Missing vs the spec (main items)

- Exit orders as **limit + buffer** with repricing and no market fallback:
  not modelled; simulated exits fill at the stop price or the gap open.
- Order/fill event records (order IDs, ack, partial fills): not present;
  journals record trades and exits only.
- Signal records do not yet store speed/signal values and parameter snapshot.
- Per-timeframe toggles (1m+3m+5m together): one resolution per session today.
- BANK NIFTY / SENSEX: resolver is NIFTY-only (strike step 50).
- Strategy settings UI, profile save/load, chart risk/reward box.
- A runner that runs a whole day (timer for forced exit, live marks).

## 8. Conflicts / risks

1. **No indicator warm-up.** The pipeline starts each day with zero bars, so
   KTMI lines differ from TradingView (which uses months of history), and none
   exist for roughly the first 13 + 8 bars. Trades in the morning would not
   match the chart.
2. Spec says entry window is configurable, handover says 09:45, code default
   09:30. Owner to confirm.
3. Spec's exit rule (limit + buffer, never market) is stricter than the current
   simulated fill model.

## 9. Prioritised plan

1. **Warm-up:** load previous sessions' candles (local DB / FYERS history) into
   the pipeline before the first live tick, and test that live KTMI equals a
   full-history calculation. Files: `paper_trading/market_data_pipeline.py`,
   `paper_trading/session.py`.
2. **Signal journal:** store speed, signal, trigger and parameter snapshot
   with every signal, including rejected ones. Files: `paper_trading/recorder.py`.
3. **Day runner:** one command that starts the session, calls the 15:10 forced
   exit, feeds live marks, and stops cleanly. New `scripts/run_paper_session.py`.
4. **Historical replay of the same engine** on stored candles, to compare
   paper results with TradingView arrows day by day.
5. Limit + buffer exit model; order event journal.
6. UI: settings panel and chart box.

## 10. First, smallest, safe step

Item 1, warm-up, because without it the paper engine's arrows will not match
the owner's chart in the morning.
